## 4. Update operation: validate, stop, write, replace (D5)

- [x] 4.1 Add `RunnerRegistry.updateSettings(mailboxId: string, overrides: Record<string, unknown>): Promise<void>` per design.md D5's six steps: look up the runner (throw `Unknown mailbox: ${mailboxId}` if absent, matching `triggerNow`'s existing precedent), validate `overrides` via `validateOverrides`/`overridableSchema` (a type failure on a recognized key rejects the whole call before anything else runs - unknown/global-only keys are dropped with a warning, not rejected), call the existing runner's `stop()`, open a throwaway connection and call `writeSettingsOverrides` against `mailbox.stateFolder` with `safeLogout` in `finally`, construct a new `MailboxRunner` for the same mailbox and call `.start()` on it (not awaited to completion - D4's bootstrap-retry loop may still be running), and replace the registry's map entry with the new runner immediately once constructed.
- [x] 4.2 Verify with unit tests: a valid update stops the old runner, writes the new settings message, and the map entry after the call resolves points at a runner whose next successful bootstrap uses the new settings (assert via the new runner's eventual `getStatus()` or a subsequent job's resolved folders/thresholds); an invalid update (type error on a recognized key) throws, and confirms via mocks/spies that neither `stop()` nor `writeSettingsOverrides` was ever called, and the original runner is still the one in the map; an update for an unknown `mailboxId` throws the same `Unknown mailbox: ...` error `triggerNow` already uses, without touching any existing runner.
- [x] 4.3 Verify the hand-edit overwrite scenario: a settings message written directly (bypassing `updateSettings`) is completely replaced - not merged - by the next `updateSettings` call, via a test that pre-writes one overrides object directly through `writeSettingsOverrides`, then calls `updateSettings` with a different, non-overlapping overrides object, and confirms the mailbox's next resolved settings match only the second call's content.
